🧠 Trouver les tags d'une vidéo avec une IA locale

Un modèle Qwen2.5-0.5B tourne dans votre navigateur (aucune donnée envoyée à un serveur). Il analyse un titre, une description ou une transcription, puis rapproche les mots-clés de votre base de tags notés. Il ne lit pas directement une URL YouTube et ne consulte pas les volumes de recherche.

IA non chargée — cliquez sur « Charger l'IA »

Le téléchargement se fait une seule fois puis le modèle est mis en cache. Comptez 350 Mo à 1 Go. WebGPU est nécessaire pour une vitesse correcte (Chrome/Edge 113+, Safari 18+).

1️⃣ Décrivez la vidéo

Utilisez ce que vous avez sous la main. Plus le texte est riche, meilleurs sont les tags.

Sans fichier : l'IA travaille sur le texte. Avec un fichier : des images clés sont extraites toutes les X secondes et analysées par un modèle vision (BLIP). Le fichier ne quitte jamais votre ordinateur.

2️⃣ Résultat de l'analyse

ℹ️ Ce que cette IA peut et ne peut pas faire

✅ Extraire mots-clés d'un titre + description + transcriptionOui
✅ Traduire un concept FR en tags EN virauxOui
✅ Décrire des images extraites d'un fichier vidéoOui (modèle vision à part)
✅ Transcrire l'audio d'une vidéoOui (Whisper, ci-dessous)
❌ Connaître les tags exacts d'une vidéo YouTube par son URLNon — impossible sans API YouTube
❌ Connaître les volumes de recherche réelsNon — les scores sont des estimations

⚠️ Un modèle de 0,5 milliard de paramètres hallucine s'il doit inventer des hashtags. C'est pourquoi il ne génère pas les tags finaux : il produit des mots-clés, que le logiciel fait correspondre à votre base de tags vérifiés. C'est le mode « RAG » — la seule façon fiable d'utiliser un petit modèle ici.

🎙️ Transcription audio (Whisper)

Pour analyser une vidéo dont vous n'avez pas le texte : un modèle Whisper local transcrit les premières secondes, puis l'IA en extrait les tags.

Modèle Whisper Tiny (~40 Mo) chargé à la demande. La transcription d'une minute d'audio prend quelques secondes en WebGPU, davantage en WASM.

🔄 Mises à jour automatiques

Votre logiciel se met à jour tout seul tous les 15 jours grâce à GitHub Actions.

1

Le 1er et le 16 de chaque mois
GitHub Actions lance automatiquement scripts/update.mjs.

2

Le script recalcule la base
Il incrémente la version, détecte les événements saisonniers actifs (Noël, Halloween, Coupe du monde, rentrée, soldes…) et injecte les tags correspondants.

3

Le site est republié
Le commit déclenche le déploiement GitHub Pages : la nouvelle version est en ligne en ~1 minute.

4

Votre app le détecte
À l'ouverture, elle compare sa version à data/version.json et affiche le badge « Nouvelle version disponible ».

🛠️ Ajouter une mise à jour à la main

Modifiez data/tags.json (ajouter des tags, changer une tendance, un conseil) puis poussez : la mise à jour se déploie immédiatement. Pour forcer un rafraîchissement saisonnier sans attendre : Actions → TagViral — Mise à jour 15 jours → Run workflow.

📴 Mode hors-ligne

Le fichier data/tags.js contient la base complète : ouvrez index.html par double-clic, tout fonctionne sans internet. La détection de nouvelle version, elle, nécessite une connexion.
